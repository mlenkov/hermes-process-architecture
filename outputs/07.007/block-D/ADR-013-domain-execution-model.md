# ADR-013: Доменная модель исполнения (domain execution model)

**Дата:** 2026-08-17
**Статус:** Утверждён
**Автор:** mais
**Профстандарты:** 06.043 (доменный), 07.007 (детерминированный)

---

## Проблема

Для доменных профстандартов (06.043 и далее) нужно выбрать модель исполнения
ТФ: нативный LLM-воркер (как предлагает Hermes Kanban) или детерминированные
навыки (как в 07.007). Решение принято на основе пилота 6b.

## Контекст

**Пилот 6b (2026-08-17, А/01.4 → keywords-filter):**
- ТФ А/01.4 «Составление списка ключевых слов» засижена на борд std-0643,
  assignee ppc, skill keywords-filter, вход — синтетические 20 запросов.
- Нативный dispatcher заспавнил LLM-воркера (профиль ppc), воркер записал
  артефакт outputs/06.043/pilot/A-01.4-keywords.yaml (5978 байт).
- Детерминированная приёмка (scripts/accept-artifact.py): YAML-структура
  валидна, все 20 запросов из входных данных (0 выдуманных сущностей),
  15 минус-слов с обоснованием → **ACCEPTED**, запись в registry 06.043
  создана (executed_by: ppc, status: covered).

**Результат пилота:** положительный.

## Решение

**Доменные стандарты (06.043 и далее):**
- **Исполнение:** нативный dispatcher Hermes (LLM-воркер, профиль-исполнитель
  из mapping).
- **Приёмка:** детерминированный слой — scripts/accept-artifact.py
  (валидация по схеме + анти-галлюцинация: сущности только из входов)
  + запись в registry.
- **Registry:** executed_by = профиль-исполнитель, status по факту покрытия.
- **07.007 сохраняет детерминированный executor** (ADR-010 не трогать):
  навыки с ## Process python-кодом, sandbox, dependency gate.

**Разграничение:**
- 07.007 — нормативная/процессная работа (регламенты, архитектура): точность
  и воспроизводимость важнее, детерминированные навыки.
- Доменные — операционная работа (маркетинг, контент): LLM-воркер + строгая
  приёмка дают скорость при сохранении контроля качества.

## Последствия

**Плюсы:**
- Доменные стандарты не требуют написания детерминированных навыков —
  достаточно существующих агентных навыков (keywords-filter и др.).
- Анти-галлюцинационная приёмка — детерминированный барьер качества.
- 07.007 не затронут.

**Минусы:**
- Зависимость от доступности LLM-провайдера у профиля-исполнителя
  (в пилоте ppc был настроен на нерабочий провайдер — исправлено на
  opencode-go).
- Токенозатраты на каждый прогон воркера (приемлемы: пилот — 1 мин работы).
- Приёмка покрывает структуру и источники данных, но не «смысловое»
  качество (HITL при необходимости — ADR-006).

## Суперседирование

Не суперседирует ADR-010 (гибрид для 07.007). Развивает ADR-011
(мульти-стандарт): доменные стандарты получают свою модель исполнения.
