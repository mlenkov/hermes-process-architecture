# ADR-012: Кросс-стандартное делегирование (cross-standard delegation)

**Дата:** 2026-08-17
**Статус:** Утверждён
**Автор:** mais
**Профстандарты:** 06.043 (делегатор), 06.013 (исполнитель контента)

---

## Проблема

ТД одного профстандарта содержат работу, относящуюся к другому стандарту.
Пример: 06.043 «Специалист по интернет-маркетингу» включает ТД по написанию
текстов (SEO-контент, рекламные объявления, посты для соцмедиа, тексты
рассылок) — это область профстандарта 06.013 (копирайтинг).

Прямое исполнение контентных ТД навыком делегатора (06.043) дублирует
компетенцию исполнителя (06.013) и ломает границы стандартов.

## Контекст

Классификация 48 ТФ 06.043 (принята 2026-08-17):

- 36 ТФ — выполняются самим 06.043 (стратегия, аналитика, управление кампаниями)
- 3 ТФ — полное делегирование в 06.013 (Е/03.5, F/03.5, G/03.5 — ТЗ на тексты/графику)
- 9 ТФ — частичное делегирование (А/02.4, А/03.4, В/01.4, В/02.4, С/02.4,
  С/03.4, D/04.5, G/02.5, J/02.6 — контентная часть ТД)

Профиль-исполнитель 06.043 — ppc-specialist; 06.013 — copywriter (существует).

## Решение

### Модель делегирования

1. **Делегируется ИСПОЛНЕНИЕ контентных ТД.** Делегирующий стандарт (06.043)
   сохраняет ТД «постановка (ТЗ) / контроль / приёмка» — это его собственная
   работа, которую исполняет его профиль.

2. **Поле mapping** — схема:

   ```yaml
   delegation:
     standard: "06.013"     # стандарт-исполнитель контентной части
     type: full|partial     # full: ТФ целиком контентная; partial: часть ТД
     note: "..."            # что именно делегируется
   ```

3. **Статусы исполнения:**
   - `delegated_full` — ТФ НЕ исполняется executor'ом делегатора (только
     постановка/приёмка через HITL).
   - `delegated_partial` — исполняются только ТД постановки/контроля/приёмки;
     контентные ТД не исполняются навыком делегатора.

4. **Registry:**
   - Запись исполнения контентной части создаётся в стандарте-исполнителе
     (06.013) — после его онбординга.
   - Делегатор фиксирует приёмку через approval-request (ADR-006):
     приёмка = HITL-запрос к результату исполнителя.

5. **До онбординга 06.013:** делегированные ТФ остаются с пометкой
   «ожидает онбординга 06.013» в documented_gaps 06.043 — без фиктивных
   записей (ADR-007).

## Последствия

**Плюсы:**
- Чистые границы стандартов: каждый исполняет свою компетенцию.
- Контентные ТД не дублируются навыками делегатора.
- Приёмка через HITL даёт контроль качества без выдумывания.

**Минусы:**
- Зависимость от онбординга 06.013 (до него делегированные ТФ не исполняются).
- HITL-приёмка требует участия оператора на каждом делегированном артефакте.

## Суперседирование

Не суперседирует другие ADR. Развивает ADR-006 (HITL), ADR-011 (мульти-стандарт).
