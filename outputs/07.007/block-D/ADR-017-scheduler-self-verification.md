# ADR-017: Scheduler-backed self-verification & watchdog

**Дата:** 2026-08-17
**Статус:** Утверждён
**Автор:** mais
**Профстандарты:** 07.007, 06.043, 06.013
**Связан с:** ADR-016 (memory), ADR-010 (гибрид), ADR-015 (события)

---

## Проблема

Система полагается на ручной мониторинг:
- validate-registry запускается вручную, нет регулярной самопроверки;
- зависшие ready-задачи (никто не подхватывает) не мониторятся;
- память о покрытии (ADR-016) обновляется, но не по расписанию.

## Контекст

- Hermes имеет встроенный scheduler (`hermes cron`) — уже используем `pdca-weekly`.
- Есть `validate-registry.py` (самопроверка), `watchdog-ready.py` (алерт на frozen ready),
  `memory-reporter.py` (кэш покрытия).
- Требование: автоматизация без ручного запуска фаз.

## Решение

**Набор cron-задач** через `hermes cron` (+ workdir на репозиторий):

| Cron | Расписание | Функция |
|------|------------|---------|
| `pdca-weekly` | 0 8 * * 1 | PDCA-цикл: покрытие, топ-3 gaps, отчёт |
| `validate-daily` | 0 8 * * * | validate 3 стандартов; ERROR → сигнал |
| `memory-reporter-daily` | 0 9 * * * | registry → Memory (ADR-016) |
| `watchdog-ready` | */15 * * * * | алерт на ready-задачи старше 30 мин |

### Правила

- Каждый cron работает из `workdir=<repo>`; перед запуском проверять `git status`
  чистый (иначе drift_skip — защита от работы при грязной копии).
- Watchdog и validate-скрипты — без side-effect'ов (только диагностика).
- При отсутствии проблем watchdog молчит (patch: watchdog-pattern).
- ERROR в validate → cron возвращает сигнал (ненулевой код) оператору.

## Последствия

- **Плюс:** автоматическая регулярная самопроверка (нет ручного запуска).
- **Плюс:** алерты на зависшие ready — снижение операционного риска.
- **Плюс:** память о покрытии актуальна ежедневно.
- **Минус:** требует дисциплины «крон не пишет в git при грязной копии»;
  local-доставка CLI — вывод смотреть через `hermes cron list`.
