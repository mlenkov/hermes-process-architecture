# ADR-016: Memory-backed registry (горячий кэш + git источник истины)

**Дата:** 2026-08-17
**Статус:** Утверждён
**Автор:** mais
**Профстандарты:** 07.007, 06.043, 06.013
**Связан с:** ADR-007 (идемпотентность), ADR-011 (мульти-стандарт)

---

## Проблема

Покрытие стандартов хранится только в `labor-coverage-registry.yaml` (git-файл).
Это версионируемый источник истины, но:
- для быстрого ответа «какое покрытие у 06.043» нужно читать файл / гонять validate;
- нет памяти о пайплайнах между сессиями (последнее исполнение, отказы, тренды);
- Registry Summary System Hermes (Memory/hot facts) не задействована.

## Контекст

- Registry — в каждом `outputs/<S>/labor-coverage-registry.yaml` (git, версии).
- Hermes имеет Memory System / fact-файлы, инжектируемые в контекст.
- Требование: не дублировать источник истины, не ломать версионирование.

## Решение

**Гибрид.** YAML остаётся единственным источником истины. Memory System = горячий
кэш фактов о покрытии, который:
- генерируется скриптом `scripts/memory-reporter.py` (читает registry → пишет
  сжатые факты в `.hermes-facts/`, gitignored);
- обновляется cron'ом `memory-reporter-daily` (ежедневно 09:00);
- даёт быстрый доступ к «горячему» состоянию без чтения файлов;
- при расхождении (RegressionDetection) отмечает регрессию.

### Правила

- Registry не изменяется скриптом (репортёр — read-only).
- Факты транзиентные (`.hermes-facts/` в .gitignore), пересоздаются ежедневно.
- Ошибочная регрессия (упавший covered/ERROR) → reporter печатает предупреждение
  для оператора/возвращает ненулевой код.

## Последствия

- **Плюс:** быстрая memory о покрытии между сессиями.
- **Плюс:** автоматическая ежедневная сводка без ручного validate.
- **Плюс:** версионирование сохранено (YAML — источник истины).
- **Минус:** два механизма (файл + память) — нужна дисциплина «memory только кэш».
