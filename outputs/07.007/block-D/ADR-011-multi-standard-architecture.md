# ADR-011: Мульти-стандартная архитектура (multi-standard namespace)

**Дата:** 2026-08-17
**Статус:** Утверждён
**Автор:** mais
**Профстандарт:** 07.007 «Специалист по процессному управлению» (базовый)

---

## Проблема

Агентство МАИС работает по нескольким профессиональным стандартам
(07.007 — процессное управление, 06.043 — интернет-маркетинг и др.).
Текущая архитектура жёстко завязана на 07.007:

- `docs/standards/07.007/` и `outputs/07.007/` — захардкожены в скриптах.
- Registry и mapping лежат в одном месте (`outputs/07.007/labor-coverage-registry.yaml`,
  `outputs/07.007/block-D/labor-function-to-skill-mapping.yaml`) без
  нейспейса стандарта.
- Профиль-исполнитель (`mais`) зашит в ADR-008 как единственный исполнитель
  для 07.007 — но для 06.043 исполнителем является другой профиль
  (`ppc-specialist`).
- Kanban-борд один — задачи разных стандартов смешиваются.

## Контекст

Требуется обобщение архитектуры на N профстандартов при соблюдении условий:

1. **07.007 неприкосновенен** — регрессия обязательна, семантика не меняется.
2. Гибридная модель (ADR-010) — финальная: нативный kanban для seeder,
   детерминированный executor для исполнения.
3. Общие механизмы (ADR-006 HITL, ADR-007 идемпотентность, ADR-009 webhooks,
   sandbox) должны работать для всех стандартов без изменения семантики.

Проверено (2026-08-17): Registry valid: True (17 записей), HEAD 0075609.

## Решение

### Нейспейс

- **Нормы:** `docs/standards/<S>/` (S = код стандарта, напр. `06.043`)
- **Артефакты:** `outputs/<S>/`
- **Registry и mapping — в корне стандарта:**
  - `outputs/<S>/labor-coverage-registry.yaml`
  - `outputs/<S>/labor-function-to-skill-mapping.yaml`
- **07.007 — legacy:** mapping исторически лежит в `outputs/07.007/block-D/`.
  Скрипты поддерживают обе схемы: для 07.007 — legacy-путь (block-D/),
  для новых стандартов — root-layout.

### Профиль-исполнитель

- Профиль per-standard указывается в заголовке mapping
  (`executor_profile:`), а не зашивается в скрипт.
  - 07.007 → `mais` (ADR-008 действует для 07.007)
  - 06.043 → `ppc-specialist`
- Скрипты читают профиль из mapping; fallback — `mais`.

### Kanban-борд

- Борд per-standard: `std-<digits>` (напр. `std-0643`).
- Флаг `--board` уже реализован в migrate-to-native-kanban.py (ADR-010);
  параметризуется стандартом: `--standard 06.043` → `--board std-0643`.

### Скрипты

- Общий флаг `--standard` (default `07.007`).
- В body задач добавляется поле `standard` (код стандарта).
- Executor выводит путь registry из `body.standard` (fallback `07.007`).
- dependency gate уже стандарт-агностичен (пути в body) — подтверждено.

### Общие механизмы

- ADR-006 (HITL), ADR-007 (идемпотентность), ADR-009 (webhooks), sandbox —
  общие для всех стандартов, без изменений семантики.

## Последствия

**Плюсы:**

- Новый стандарт подключается добавлением директории + mapping — скрипты не меняются.
- Профиль-исполнитель декларируется в mapping, не в коде.
- Задачи стандартов изолированы на уровне kanban-бордов и output-директорий.
- 07.007 остаётся рабочим (legacy-пути поддерживаются).

**Минусы:**

- Два пути к mapping (legacy block-D/ для 07.007 и root для новых) — надо
  поддерживать обе ветки в скриптах.
- Бордов становится несколько — нужна дисциплина `--standard` при вызовах.

## Суперседирование

Не суперседирует другие ADR. Развивает ADR-008 (профиль-исполнитель в
контексте одного стандарта), ADR-010 (гибрид), ADR-004 (mapping как
источник истины). ADR-008 продолжает действовать для 07.007.
