# ADR-005: Интеграция Graphify — исполняемый функциональный IDEF0-граф

**Дата:** 2026-08-01
**Статус:** Предложен (ожидает утверждения)
**Автор:** architect
**Профстандарт:** 07.007 «Специалист по процессному управлению»

---

## Проблема

Бизнес-процессы документируются в виде визуальных Mermaid-диаграмм
(`docs/processes/*.mmd`). Mermaid описывает, *как выглядит* процесс, но не является
**исполняемой моделью**:

- Отсутствует машинная проверка консистентности: обрывы pipeline, тупиковые ТД,
  артефакты без владельца не обнаруживаются автоматически.
- Нет связей ТД→артефакт→ТД, которые можно проверять при исполнении.
- Нельзя вычислить путь/покрытие между ТФ (`graphify path "LF-07.007-A/01.6" ...`),
  трассировать разрывы и строить рекомендации на основе топологии.

## Контекст

`graphify-out/.graphify_semantic.json` (Dobsongraph-формат, ~315 узлов, 2263 ребра)
уже строится скриптом `scripts/build-graph-from-yaml.py`. Но:

- Граф собирается **разово** как артефакт анализа, а не поддерживается навыками.
- Структура смешивает узлы-ТФ, узлы-skills, узлы-knowledge и профили — часть графа
  носит социальный характер (кто-что делает), а не функциональный.
- Навык `crossfunction-graph-builder` (В/02.6) уже генерирует свой IDEF0-граф,
  но в собственном формате, отдельно от `graphify-out/`.

## Варианты

### А: Оставить Mermaid-диаграммы как единственную модель

**Плюсы:** нет изменений, привычные диаграммы.
**Минусы:** не исполняемая модель; консистентность не проверяется; граф и диаграммы расходятся.

### Б: Исполняемый семантический граф как источник истины (ВЫБРАН)

Навыки (в первую очередь `crossfunction-graph-builder`, далее все навыки,
работающие с pipeline) генерируют и обновляют `graphify-out/.graphify_semantic.json`.

**Плюсы:** единая исполняемая модель; машинная проверка разрывов; используются
существующие инструменты `graphify query/path/explain`; покрытие ТД трассируемо.
**Минусы:** нужна конвенция структуры узлов/рёбер; навыки обязаны проверять
консистентность перед записью.

### В: Генерировать отдельный граф на каждую ТФ

**Плюсы:** изоляция.
**Минусы:** N графов, нет целостной модели; слияние сложно.

## Решение

**Выбран вариант Б.** `graphify-out/.graphify_semantic.json` становится
**исполняемой моделью процессов** (функциональный IDEF0-граф) и обновляется навыками.

### Правила модели

| Аспект | Правило |
|--------|---------|
| Узел | Трудовая функция (ТФ): `LF-07.007-X/XX.X` |
| Ребро | `artifact_handoff` — передача артефакта от `source_tf` к `target_tf` |
| Механизм | профиль + навык (`executed_by`, `skill_path`) — **атрибуты узла**, не отдельные узлы |
| Запрет | НЕ создавать узлы-профили и узлы-навыки (избегаем «социального графа») |
| Консистентность | перед записью навык проверяет отсутствие разрывов pipeline (каждая ТФ достижима, каждый ТД имеет предка/наследника) |
| Валидация | после записи — проверка структуры узлов и рёбер по схеме графа |

### Атрибуты узла

```yaml
node:
  id: LF-07.007-В/02.6
  tf_name: Моделирование кросс-функционального процесса
  block: B
  executed_by: analyst                        # механизм — атрибут, не узел
  skill_path: profiles/analyst/skills/crossfunction-graph-builder/SKILL.md
  coverage_status: partially_covered
  artifacts_out:                              # что узел передаёт дальше
    - outputs/07.007/block-B/B-02.6-graph-consistency.yaml
```

### Обновляющие навыки

1. `crossfunction-graph-builder` (В/02.6) — основной писатель графа.
2. Любой навык, изменяющий pipeline/артефакты (`crossfunction-designer`,
   `crossfunction-deployer`) — обновляет свою часть графа и проверяет консистентность.

## Последствия

- **Плюс:** Mermaid остаётся визуализацией, семантический граф — источником истины.
- **Плюс:** разрывы pipeline обнаруживаются автоматически (до исполнения).
- **Минус:** требуется обновить `crossfunction-graph-builder` и добавить
  консистентность-проверку (в связке с ADR-007 Pre-flight).
- **Минус:** конвенция структуры графа фиксируется в `new-skill-architecture-blueprint.md`.
