# New Skill Architecture Blueprint

**Профстандарт:** 07.007 «Специалист по процессному управлению»
**Профиль-исполнитель:** mais (ADR-008 — единственный исполнитель 07.007)
**Назначение:** Жёсткий шаблон для создания любого нового навыка (SKILL.md) в системе Hermes.
**Версия:** 1.0.0

---

## 1. Входные триггеры и контекст

### 1.1 Единственный способ запуска

Навык запускается **исключительно** через kanban-задачу, созданную seeder'ом (`architect-seeder`) из YAML execution block'а профстандарта.

Триггерная цепочка:
```
seed-tf-pipeline.py → kanban create (status=todo) → auto-promote → status=ready
    → architect-executor выполняет claim → загружает td-gen SKILL.md
    → td-gen исполняет код → kanban complete
```

### 1.2 Контекст, который навык получает на входе

Каждый td-gen SKILL.md получает от executor'а следующие переменные:

| Переменная | Тип | Источник | Описание |
|------------|-----|----------|----------|
| `body` | dict | kanban task body | la_id, parent_tf, input_files, output_dir, output_files |
| `input_files` | list[str] | kanban body | Пути к файлам-входам предыдущих ТД |
| `output_dir` | str | kanban body | Директория для записи результатов |
| `output_files` | list[str] | kanban body | Полные пути к файлам, которые должен создать навык |
| `os` | module | executor | Стандартный os |
| `yaml` | module | executor | Стандартный yaml (PyYAML) |
| `re` | module | executor | Стандартный re |
| `subprocess` | module | executor | Стандартный subprocess |
| `json` | module | executor | Стандартный json |
| `pathlib` | module | executor | Стандартный pathlib |
| `print` | function | executor | Для логирования |

### 1.3 Источники данных для чтения

Навык имеет **только read-доступ** к следующим файлам (право чтения, никогда записи):

```
# Текущее состояние архитектуры
../AGENTS.md                           — профили AI-команды (только для справки)
docs/standards/07.007/                  — директория профстандарта
  otf-section-1.yaml                    — YAML-представление ОТФ-A
  otf-section-2.yaml                    — YAML-представление ОТФ-B
  otf-section-3.yaml                    — YAML-представление ОТФ-C
  otf-section-4.yaml                    — YAML-представление ОТФ-D
  meta.yaml                             — метаданные стандарта

# Текущие артефакты архитектуры (generated by previous TD)
outputs/07.007/labor-coverage-registry.yaml   — реестр покрытия
outputs/07.007/block-D/labor-function-to-skill-mapping.yaml — карта ТФ→skill
outputs/07.007/block-<X>/                     — outputs предыдущих ТД
outputs/07.007/pdca-reports/                   — история PDCA

# Эталонные схемы
schemas/07.007-d/<schema-name>.yaml            — схемы валидации

# Собственная конфигурация профиля
profiles/mais/SOUL.md                     — описание профиля
profiles/mais/skills/<skill-name>/SKILL.md — соседние навыки
```

### 1.4 Директория для записи (единственная)

Каждый навык пишет **строго** в свою директорию `output_dir`, которая имеет плоскую структуру внутри блока:

```
outputs/07.007/block-<X>/<X>-<tf-code>-<artifact-name>[-la<xxx>].yaml
```

Правила:
- Имя файла содержит блок, ТФ и суть артефакта (человекочитаемо)
- `la-001` не пишется в имени (подразумевается по умолчанию)
- LA-002+ добавляют суффикс `-la002`
- Вся метаинформация — внутри `meta:` ключа самого артефакта

Пример:
```
outputs/07.007/block-A/A-02.6-regulation.yaml
outputs/07.007/block-D/D-01.7-stakeholder-mapping.yaml
outputs/07.007/block-D/D-01.7-stakeholder-mapping-la002.yaml
```

## 2. Алгоритм исполнения (Pipeline)

Каждый td-gen SKILL.md следует строгому 6-шаговому алгоритму: **Шаг 0 (Pre-flight Check, ADR-007)** —
обязательная преамбула, за ней Шаги 1–5.

### Шаг 0: Pre-flight Check (идемпотентность, ADR-007)

Перед генерацией навык обязан проверить текущее состояние (ADR-007). Если целевой артефакт уже
существует, валиден и registry синхронизирован — навык завершается успешно без перегенерации.

```python
# ── Шаг 0: Pre-flight Check (идемпотентность, ADR-007) ────────────
la_id = body.get("la_id", "")
parent_tf = body.get("parent_tf", "")
tf_code = parent_tf.replace("LF-07.007-", "") if parent_tf else "unknown"

current_skill_path = "profiles/<profile>/skills/<skill-name>/SKILL.md"
registry_path = os.path.join(ARCH_DIR, "outputs/07.007/labor-coverage-registry.yaml")

if output_files:
    target = output_files[0]
    if os.path.exists(target):
        try:
            existing = yaml.safe_load(open(target, encoding="utf-8")) or {}
        except Exception:
            existing = {}
        if existing.get("quality", {}).get("schema_valid") is True:
            reg_data = read_yaml(registry_path)
            reg_entry = reg_data.get(parent_tf) or reg_data.get(f"LF-07.007-{tf_code}") or {}
            reg_ok = reg_entry.get("status") in ("covered", "partially_covered")
            skill_ok = str(reg_entry.get("skill_path", "")).endswith(current_skill_path)
            if reg_ok and skill_ok:
                print("[INFO] Artifact already exists and is valid. Registry is up to date. Skipping generation.", flush=True)
                os._exit(0)
```

### Шаг 1: Чтение контекста

```python
import os, yaml, re, json

ARCH_DIR = os.path.abspath(".")

def read_yaml(path):
    with open(path) as f:
        return yaml.safe_load(f) or {}

# Контекст из body (la_id, parent_tf, tf_code) уже прочитан в Шаге 0

# Прочитать артефакты предыдущих ТД (если есть)
input_artifacts = {}
for fpath in input_files:
    data = read_yaml(fpath)
    basename = os.path.basename(fpath).replace(".yaml", "")
    input_artifacts[basename] = data

# Прочитать labor-function-to-skill-mapping (для self-check)
mapping = read_yaml(os.path.join(
    ARCH_DIR, "outputs/07.007/block-D/labor-function-to-skill-mapping.yaml"
))

# Прочитать эталонную схему для валидации (если есть)
schema_path = os.path.join(ARCH_DIR, f"schemas/07.007-d/{...}.yaml")
schema = read_yaml(schema_path) if os.path.exists(schema_path) else {}
```

### Шаг 2: Генерация артефакта

```python
artifact_id = os.path.basename(output_files[0]).replace(".yaml", "")

result = {
    "meta": {
        "artifact": artifact_id,
        "tf": tf_code,
        "la": la_id,
        "generated_by": f"td-gen-{tf_code.replace('/','-')}-{la_id}",
        "timestamp": os.popen("date -u +%Y-%m-%dT%H:%M:%SZ").read().strip(),
        "schema_ref": f"{artifact_id}-schema.yaml v1.0.0"
    },
    "body": {
        # Основное содержание — специфично для каждой ТД
    },
    "quality": {
        "schema_valid": True,        # результат валидации
        "data_sources": input_files  # что было прочитано
    }
}
```

### Шаг 3: Валидация

```python
def validate_result(result, schema):
    """Проверить result на соответствие schema."""
    if not schema:
        return True
    # Проверить обязательные поля
    required = schema.get("required_fields", [])
    for field in required:
        if field not in result:
            print(f"  [VALIDATION] missing required field: {field}")
            return False
    return True

is_valid = validate_result(result, schema)
result["quality"]["schema_valid"] = is_valid
if not is_valid:
    print("  [WARN] output failed schema validation — writing anyway")
```

### Шаг 4: Запись

```python
os.makedirs(output_dir, exist_ok=True)

# Записать основной артефакт
primary_path = output_files[0]  # первый output_file = основной
with open(primary_path, "w") as f:
    yaml.dump(result, f, allow_unicode=True, default_flow_style=False, sort_keys=False)
```

### Шаг 5: Отчёт

```python
print(f"  Written: {primary_path}")
print(f"  Schema valid: {is_valid}")
print(f"  Artifact: {artifact_id}")
```

## 3. Стандарт артефактов

### 3.1 Формат

Все артефакты — **YAML** (расширение `.yaml`). Исключение: Mermaid-диаграммы — `.mmd`.

### 3.2 Нейминг

```
<artifact-type>.yaml
```

Где `artifact-type` — kebab-case английское имя. Примеры:

| ТД | Имя файла |
|----|-----------|
| D/01.7 la-001 | `stakeholder-mapping-instance.yaml` |
| D/01.7 la-004 | `architecture-data-instance.yaml` |
| D/02.7 la-002 | `reference-model-selection.yaml` |
| D/02.7 la-004 | `target-architecture-design.yaml` |
| D/03.7 la-001 | `transformation-plan.yaml` |
| D/04.7 la-001 | `methodology-created.yaml` |

Запрещены:
- Кириллица в именах файлов
- Пробелы
- Не-ASCII символы

### 3.3 Базовая структура YAML

Каждый артефакт обязан содержать корневые ключи `meta` и `quality`. Вся метаинформация (идентификация, происхождение, время, источники) хранится **только** в `meta` и `quality` ключах самого файла. Отдельных файлов метаданных не создаётся (ADR-002).

`meta` содержит:

```yaml
meta:
  artifact: <artifact-type>
  tf: D/01.7
  la: la-001
  generated_by: td-gen-D-01.7-la-001
  timestamp: 2026-07-29T12:00:00Z
  schema_ref: stakeholder-mapping-schema.yaml v1.0.0
```

И корневой ключ `quality`:

```yaml
quality:
  schema_valid: true
  awaiting_approval: false        # опционально (ADR-006): true = HITL-точка
  data_sources:
    - docs/standards/07.007/otf-section-4.yaml
    - ../AGENTS.md
```

Содержание артефакта — в корневых ключах между `meta` и `quality` (например `body`, `stakeholders`, `plan`, `methodology`).

### 3.3a Human-in-the-Loop (HITL, ADR-006)

Если ТД профстандарта требует решения человека (User_Operator), навык:

1. **НЕ выдумывает решение** — никаких вымышленных имён, дат, вендоров, бюджетов.
2. Пишет файл-запрос `approval-request` **рядом с основным артефактом**.
3. Ставит `quality.awaiting_approval: true` в основном артефакте.
4. Завершается успешно (pipeline не блокируется) — решение приходит позже.

Если HITL не требуется — поле `awaiting_approval` отсутствует или `false`.

**Именование approval-request** — производное от `output_files[0]`:

```
X-XX.X-<artifact>.yaml  →  X-XX.X-<artifact>-approval-request.yaml
```

Пример: `C-03.7-implementation-plan.yaml` →
`C-03.7-implementation-plan-approval-request.yaml`.

**Шаблон approval-request** (из ADR-006):

```yaml
# approval-request-schema.yaml v1.0.0
approval_request:
  request_id: str          # APR-01
  tf_code: str             # ТФ, в которой требуется решение
  source_td: str           # ТД профстандарта, требующее HITL
  question: str            # что именно решает человек
  options:
    - option_id: str       # OPT-A
      label: str
      description: str
  context_ref: str         # артефакт/файл с контекстом
  deadline: null           # при наличии ТД — строка ISO; иначе null
```

**Правило формирования options:** варианты — это **классы решений**, извлечённые из
реальных артефактов (например, `resource_requirements` roadmap: RES-01/RES-02),
**БЕЗ названий вендоров** (никаких «внедрить MS Dynamics» — только класс решения,
например «расширить текущий стек graphify+kanban»).

### 3.4 Директории

```
ARCHITECTURE/
  outputs/07.007/
    labor-coverage-registry.yaml         # корень — читают все блоки
    block-D/
      labor-function-to-skill-mapping.yaml # карта ТФ→skill (использует executor)
      D-01.7-stakeholder-mapping.yaml
      D-01.7-stakeholder-mapping-la002.yaml
      D-02.7-architecture-designed.yaml
      D-03.7-transformation-plan.yaml
      D-04.7-methodology-developed.yaml
    block-A/
      A-01.6-info-context.yaml
      A-02.6-regulation.yaml
```

Каждый навык пишет **только** в свой блок. Никогда не пишет в соседние блоки или корень.

## 4. Механизм самоконтроля и отчётности

### 4.1 Coverage registry (архитектор-уровень)

После complete TF-summary задачи `architect-executor` (или `architect-coverage`) обновляет:

```
outputs/07.007/labor-coverage-registry.yaml
```

Формат записи:

```yaml
LF-07.007-<tf-code>:
  executed_by: mais
  last_executed: 2026-07-29T12:00:00Z
  status: covered              # covered | partially_covered | missing_skill
  tds_completed: <N>/<M>
  skill_path: profiles/mais/skills/<skill-name>/SKILL.md
   artifacts_generated:
     - outputs/07.007/block-D/D-01.7-stakeholder-mapping.yaml
  pdca_ref: pdca-2026-07-29.yaml
```

**Правило:** Запись создаётся ТОЛЬКО когда все ТД в ТФ выполнены (pipeline complete). Никаких partial записей.

### 4.2 Мониторинг

`architect-monitor` пишет:

```
outputs/07.007/monitor/<YYYYMMDD_HHMMSS>.yaml
```

Формат:

```yaml
timestamp: 2026-07-29T12:00:00Z
stats:
  ready: 0
  running: 0
  blocked: 0
  done: 26
  total: 26
actions:
  - executor: none (no ready tasks)
  - selfheal: none (no blocked tasks)
```

### 4.3 PDCA-отчёты

Еженедельно (или по запросу) `pdca-reporter` формирует:

```
outputs/07.007/pdca-reports/pdca-<YYYY-MM-DD>.yaml
```

Формат:

```yaml
meta:
  type: pdca-report
  generated_by: pdca-reporter
  period:
    start: 2026-07-22
    end: 2026-07-29
plan:
  target_coverage: 35.0%
  target_tfs: 18
  priority_focus: "блок B (5 ТФ) — кросс-функциональные процессы"
do:
  executed_tfs:
    - D/01.7: covered (8/8)
    - D/02.7: covered (6/6)
    - D/03.7: covered (3/3)
    - D/04.7: covered (5/5)
  new_skills_created: 0
check:
  current_coverage: 33.3% (6/18)
  delta: -1.7% от цели
  gaps:
    - "Блок B: 0/5 ТФ — полностью отсутствует"
    - "Блок C: 2/5 ТФ — требуется PDCA-расширение"
act:
  recommendations:
    - "Создать architect-crossfunction-{analyzer,modeler,designer,deployer,auditor} — 5 навыков"
    - "Установить цель на следующий PDCA: блок B partial coverage"
  escalated: false
```

Каждый новый навык делает запись в `progress.md`:

```
## YYYY-MM-DD
```

## 5. Правила изоляции

### 5.1 Идемпотентность (ADR-007)

Любой навык может быть выполнен **многократно** без побочных эффектов:
- Перед генерацией каждый навык выполняет **Шаг 0 (Pre-flight Check)** (ADR-007).
- Если `output_files[0]` уже существует, `quality.schema_valid == true` и запись в
  `labor-coverage-registry.yaml` имеет `status: covered|partially_covered` с верным
  `skill_path` — навык **пропускает генерацию** (лог
  `[INFO] Artifact already exists and is valid. Registry is up to date. Skipping generation.`)
  и завершается успешно (exit 0), не перезаписывая данные.
- Если артефакт отсутствует / невалиден / registry рассинхронизирован — навык
  **перегенерирует** артефакт и синхронизирует registry.
- Никакой инкрементальной логики (не добавлять к существующему, а заменять).

### 5.2 Sandbox записи

Навык пишет **только** в `output_dir`. Запрещено:
- Писать в `docs/standards/07.007/` — read-only священные данные
- Писать в `profiles/mais/SOUL.md` — изменение профиля только через blueprint
- Писать в `../AGENTS.md` — вышестоящая директория
- Писать в `scripts/` или `schemas/` — инструментальные директории
- Писать в `.opencode/` — конфигурация инструмента

Единственное исключение: `outputs/07.007/labor-coverage-registry.yaml` — его обновляет ТОЛЬКО `architect-coverage`, и только после complete TF-summary.

### 5.3 Read-only источники

Навык может читать любые файлы в `../AGENTS.md`, `docs/`, `outputs/`, `profiles/`, `schemas/`, но никогда не пишет туда.

### 5.4 Никаких subprocess к Hermes

Навык **не вызывает** `hermes kanban` команды. Это делает только `architect-executor` и `architect-monitor`. td-gen навык — pure data generator, без side effects на kanban.

### 5.5 Никаких human-readable имён

В генерируемых YAML **запрещены**:
- Имена реальных людей (если не из AGENTS.md)
- Названия компаний
- Вымышленные организации
Всё, что не извлекается из реальных файлов системы — не должно попадать в output.

## 6. Чеклист готовности навыка

Перед созданием нового SKILL.md проверь:

- [ ] SKILL.md содержит `name` и `description` в frontmatter
- [ ] `description` начинается с глагола действия
- [ ] В секции `## Process` есть Шаг 0 (Pre-flight Check, ADR-007) + 5-шаговый pipeline
- [ ] Шаг 0 проверяет `output_files[0]` (exists + `schema_valid`) и синхронность `labor-coverage-registry.yaml` (status + skill_path)
- [ ] Код читает контекст из body, input_files, output_dir, output_files
- [ ] Код НЕ вызывает `subprocess` для `hermes`
- [ ] Код пишет ТОЛЬКО в `output_dir`
- [ ] Код НЕ генерирует вымышленные имена
- [ ] В секции `## Схемы данных` указан путь к schema.yaml

---

## 6.5 Делегирование в другой стандарт (ADR-012)

Если ТФ стандарта содержит ТД, относящиеся к другому стандарту (например,
06.043 → 06.013 копирайтинг):

- **Поле delegation в mapping** (схема):

  ```yaml
  delegation:
    standard: "06.013"     # стандарт-исполнитель контентной части
    type: full|partial     # full: ТФ целиком контентная; partial: часть ТД
    note: "что делегируется"
  ```

- **Правило:** делегированная контентная часть НЕ исполняется навыком
  делегатора. Делегатор исполняет только ТД «постановка (ТЗ) / контроль /
  приёмка»; сама контентная работа выполняется стандартом-исполнителем.
- Приёмка результата исполнителя — через approval-request (ADR-006).
- До онбординга стандарта-исполнителя делегированные ТФ числятся в
  documented_gaps с пометкой «ожидает онбординга <код>» — без фиктивных записей.

## 8. Пример minimal td-gen SKILL.md для нового навыка

### Rules (DO / DON'T)

**ВСЕГДА ДЕЛАЙ:**
- DO: проверяй существование файла перед `open()`. Используй `os.path.exists()`.
- DO: оборачивай `yaml.safe_load()` в `try/except`. Файл может быть битым или пустым.
- DO: извлекай данные ТОЛЬКО из реальных файлов системы (`input_files`, `docs/standards/`, `AGENTS.md`).

**КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО:**
- DON'T: генерировать вымышленные имена, компании, организации. Все данные — только из файлов.
- DON'T: вызывать `subprocess.run(["hermes", ...])` из td-gen. Это делает executor.
- DON'T: писать за пределы `output_dir`. Каждый навык пишет только в свою директорию.
- DON'T: использовать `input()` или интерактивный ввод. Навык работает без пользователя.

### Thinking Process

Перед генерацией кода ИИ обязан кратко описать свои шаги в Markdown. Это активирует Chain of Thought и предотвращает пропуск шагов.

Пример:

```markdown
## Thinking Process

1. Прочитаю labor-function-to-skill-mapping.yaml — получу список ТФ и их статус
2. Прочитаю otf-section-4.yaml — получу список трудовых действий для D/01.7
3. Прочитаю outputs/07.007/block-D/D-01.7-stakeholder-mapping.yaml — получу текущую карту стейкхолдеров
4. Проверю: файлы существуют? Если нет — запишу ошибку и завершу
5. Сформирую result = {meta, body, quality} по шаблону blueprint
6. Запишу в output_files[0] (meta уже внутри файла)
```

### Process

```python
import os, yaml

ARCH_DIR = os.path.abspath(".")

def read_file(path):
    """Прочитать YAML-файл с защитой от ошибок."""
    if not os.path.exists(path):
        print(f"  [WARN] file not found: {path}")
        return {}
    try:
        with open(path) as f:
            data = yaml.safe_load(f)
            return data if isinstance(data, dict) else {}
    except Exception as e:
        print(f"  [WARN] read error: {path}: {e}")
        return {}

def write_yaml(path, data):
    """Атомарная запись YAML: temp-файл + os.rename (POSIX, Фаза 2A)."""
    dir_name = os.path.dirname(path) or "."
    os.makedirs(dir_name, exist_ok=True)
    import tempfile
    fd, tmp_path = tempfile.mkstemp(dir=dir_name, suffix=".yaml.tmp")
    try:
        with os.fdopen(fd, "w") as f:
            yaml.dump(data, f, allow_unicode=True, default_flow_style=False, sort_keys=False)
        os.rename(tmp_path, path)
        return True
    except Exception as e:
        try:
            os.unlink(tmp_path)
        except OSError:
            pass
        print(f"  [ERROR] write error: {path}: {e}")
        return False

# ── Шаг 0: Pre-flight Check (идемпотентность, ADR-007) ────────────────────────────────────────────────

la_id = body.get("la_id", "")
parent_tf = body.get("parent_tf", "")
tf_code = parent_tf.replace("LF-07.007-", "") if parent_tf else "unknown"

print(f"  TF: {tf_code}, LA: {la_id}")

current_skill_path = "profiles/<profile>/skills/<skill-name>/SKILL.md"
registry_path = os.path.join(ARCH_DIR, "outputs/07.007/labor-coverage-registry.yaml")

if output_files:
    target = output_files[0]
    if os.path.exists(target):
        try:
            existing = yaml.safe_load(open(target, encoding="utf-8")) or {}
        except Exception:
            existing = {}
        if existing.get("quality", {}).get("schema_valid") is True:
            reg_data = read_file(registry_path)
            reg_entry = reg_data.get(parent_tf) or reg_data.get(f"LF-07.007-{tf_code}") or {}
            reg_ok = reg_entry.get("status") in ("covered", "partially_covered")
            skill_ok = str(reg_entry.get("skill_path", "")).endswith(current_skill_path)
            if reg_ok and skill_ok:
                print("[INFO] Artifact already exists and is valid. Registry is up to date. Skipping generation.", flush=True)
                os._exit(0)
# ── Шаг 1: Контекст ────────────────────────────────────────────────

# Прочитать входные артефакты
input_artifacts = {}
for fpath in (input_files or []):
    if not os.path.exists(fpath):
        print(f"  [WARN] input not found: {fpath}")
        continue
    data = read_file(fpath)
    basename = os.path.basename(fpath).replace(".yaml", "")
    input_artifacts[basename] = data

print(f"  Inputs read: {len(input_artifacts)}/{len(input_files or [])}")

# ── Шаг 2: Генерация ───────────────────────────────────────────────

if not output_files:
    print("  [ERROR] no output_files specified in body")
    # Выйти нельзя без complete — executor продолжит
    os._exit(1)

output_path = output_files[0]
artifact_id = os.path.basename(output_path).replace(".yaml", "")

# Прочитать labor-function-to-skill-mapping для self-check
mapping = read_file(os.path.join(
    ARCH_DIR, "outputs/07.007/block-D/labor-function-to-skill-mapping.yaml"
))

# Сформировать результат
result = {
    "meta": {
        "artifact": artifact_id,
        "tf": tf_code,
        "la": la_id,
        "generated_by": f"td-gen-{tf_code.replace('/','-')}-{la_id}",
        "timestamp": os.popen("date -u +%Y-%m-%dT%H:%M:%SZ").read().strip(),
        "schema_ref": f"{artifact_id}-schema.yaml v1.0.0"
    },
    "body": {
        # Специфичное содержание — заполняется под каждую ТД
    },
    "quality": {
        "schema_valid": True,
        "data_sources": [os.path.basename(p) for p in (input_files or [])]
    }
}

# ── Шаг 3: Валидация (опционально) ─────────────────────────────────

schema_path = os.path.join(ARCH_DIR, f"schemas/07.007-d/{artifact_id}.yaml")
if os.path.exists(schema_path):
    schema = read_file(schema_path)
    required = schema.get("required_fields", [])
    missing = [f for f in required if f not in result]
    if missing:
        print(f"  [VALIDATION] missing required fields: {missing}")
        result["quality"]["schema_valid"] = False
    else:
        result["quality"]["schema_valid"] = True

# ── Шаг 4: Запись ──────────────────────────────────────────────────

ok = write_yaml(output_path, result)
if not ok:
    print("  [ERROR] failed to write primary artifact")
    os._exit(1)

# ── Шаг 5: Отчёт ───────────────────────────────────────────────────

print(f"  Written: {output_path}")
print(f"  Artifact: {artifact_id}")
print(f"  Schema valid: {result['quality']['schema_valid']}")
```
