# ADR-003: Multi-Profile Distribution для 07.007

**Статус:** Утверждён
**Дата:** 2026-07-30
**Автор:** architect

---

## Проблема

Профиль `architect` содержит все 18 навыков профстандарта 07.007. Это создаёт три проблемы:

1. **Перегрузка контекста LLM.** Один профиль отвечает за регламентацию (A), кросс-функциональные взаимодействия (B), систему управления (C) и трансформацию (D) — четыре разных роли.
2. **Искусственность кросс-функциональности.** Блок B описывает взаимодействие между разными подразделениями. Внутри одного профиля это вырождается в self-talk.
3. **Масштабирование.** Каждый новый блок требует дописывать `architect-executor` и расширять mapping. Профиль становится монолитным.

## Решение

Разделить 18 ТФ 07.007 на 4 профиля + 1 слой утилит:

| Профиль | Блок | Роль | Навыки |
|---------|:----:|------|--------|
| `.default` | — | Сквозные утилиты | registry-updater, log-rotation, basic-validation |
| `regulator` | A | Регламентация процессов | info-gatherer, regulation-writer, deployment-planner |
| `architect` | D | Трансформация архитектуры | monitor, executor, seeder, pdca, selfheal, coverage |
| `analyst` | B, C | Кросс-функциональный анализ и аудит | *(пусто, готовится к наполнению)* |

## Маппинг блоков на профили

```
                        ┌─────────────────┐
                        │   .default      │
                        │ registry-updater│
                        └────────┬────────┘
                                 │ вызывает
          ┌──────────────────────┼──────────────────────┐
          ▼                      ▼                      ▼
┌──────────────────┐  ┌──────────────────┐  ┌──────────────────┐
│   regulator      │  │    analyst       │  │   architect      │
│ (Блок A)         │◄─┤ (Блоки B + C)   ├─►│ (Блок D)         │
│ info-gatherer    │  │ (B/01-B/05)      │  │ monitor          │
│ regulation-writer│  │ (C/01-C/05)      │  │ executor         │
│ deployment-planner│  │                  │  │ seeder           │
└──────────────────┘  └──────────────────┘  │ pdca             │
                                            │ selfheal         │
                                            │ coverage         │
                                            └──────────────────┘
```

**Ключевой принцип:** Блок B (кросс-функциональные процессы) теперь описывает **реальное** взаимодействие между профилями `regulator` и `analyst`. Блок C (аудит системы управления) — аудит `regulator` и `analyst` со стороны `architect` и `.default`.

## Преимущества

1. **Разделение ответственности.** Каждый профиль отвечает за свой блок. Ошибки в A не влияют на D.
2. **Реальная кросс-функциональность.** Блок B становится каналом между `regulator` и `analyst`. Коммуникация через Hermes handoff.
3. **Разгрузка контекста LLM.** Каждый профиль помнит только свои навыки (3–6 вместо 18).
4. **Независимое развёртывание.** Обновление `regulator` не требует остановки `architect`.

## Примечание: .default

`.default` — специальный профиль Hermes, чьи навыки доступны всем профилям. Сюда выносим атомарные операции (обновление registry, базовая валидация), чтобы избежать дублирования логики в каждом бизнес-профиле. Подробная реализация — на следующем этапе.
