# ADR-008: Единый профиль mais — консолидация исполнителей 07.007

**Дата:** 2026-08-16
**Статус:** Утверждён
**Автор:** mais
**Профстандарт:** 07.007 «Специалист по процессному управлению»
**Суперседирует:** ADR-003 (multi-profile distribution)

---

## Проблема

Архитектура 07.007 была разделена на 4 профиля (regulator/analyst/architect/.default)
решением ADR-003. Практика показала:

1. **Разделение ответственности не работает на практике.** Профили regulator/analyst/architect
   не являются отдельными агентами Hermes — они существуют только как директории навыков.
   Реальный исполнитель стандарта один: профиль `mais` (COO, специалист по процессному
   управлению). Мнимые профили создают иллюзию распределённости без исполняемой разницы.
2. **Перегрузка mapping и registry.** Каждая запись registry должна указывать на
   `executed_by` и `skill_path`; тройная схема профилей удваивает пути и усложняет
   резолвинг (KNOWN_PROFILES, fallback, resolve_profile).
3. **Кросс-функциональность блоков B/C вырождается в self-talk.** Разделение на
   профили не создаёт реального канала коммуникации — один и тот же исполнитель
   (mais) выполняет все ТФ последовательно через pipeline.
4. **Ошибка в ADR-003:** в его собственном «Изменения в структуре директорий»
   профиль `analyst` был перечислен дважды, а профиль mais описан как «существующий»
   среди равных — при том что остальные профили (ppc-specialist, copywriter и т.д.)
   относятся к другим профстандартам агентства, а не к 07.007.

## Контекст

- Профстандарт 07.007 содержит 18 ТФ (блоки A–D), все они в рамках одного
  профессионального стандарта «Специалист по процессному управлению».
- Единственный профиль Hermes, исполняющий 07.007, — **mais** (Айра, COO).
- Существующие директории `profiles/regulator/skills/`, `profiles/analyst/skills/`,
  `profiles/architect/skills/` содержат навыки блоков A/B/C/D, которые фактически
  выполняются профилем mais.
- Профиль `.default` — служебный слой Hermes (registry-updater), остаётся нетронутым.
- Решения ADR-005 (Graphify), ADR-006 (HITL), ADR-007 (идемпотентность) приняты и
  не затрагиваются данной консолидацией.

## Решение

**Единственный исполнитель профстандарта 07.007 — профиль `mais`.**
Все навыки 07.007 переезжают в `profiles/mais/skills/`. Профили
regulator/analyst/architect удаляются.

### Правила

1. **Единый исполнитель:** `executed_by: mais` во всех записях registry и артефактах.
2. **Единая директория навыков:** все SKILL.md — в `profiles/mais/skills/<name>/SKILL.md`.
3. **ADR-003 суперседирован:** multi-profile distribution отменяется; префикс
   `architect-*` сохраняется только как **функциональное пространство имён**
   («инженерия архитектуры», блок D), а не как указатель на профиль.
4. **`current_skill_path`** в каждом SKILL.md указывает на
   `profiles/mais/skills/<name>/SKILL.md`.
5. **Резолвинг:** KNOWN_PROFILES/fallback в скриптах заменяется константой
   `CURRENT_PROFILE = "mais"`; `resolve_profile()` всегда возвращает `"mais"`.
6. **Документированный gap С/05.7 сохраняется** — консолидация не меняет покрытие ТФ.
7. **HITL/webhooks не реализуются в рамках данного ADR** — отдельная фаза.

### Структура после консолидации

```
profiles/
├── .default/                     # служебный слой Hermes (НЕ трогаем)
│   └── skills/registry-updater/
└── mais/                         # единственный исполнитель 07.007
    └── skills/
        ├── info-gatherer/            # A/01.6
        ├── regulation-writer/        # A/02.6
        ├── deployment-planner/       # A/03.6
        ├── crossfunction-analyzer/   # B/01.6
        ├── crossfunction-designer/   # B/02.6
        ├── ...                       # все 07.007-навыки
        └── td-gen/                   # сгенерированные ТД-навыки блока D
```

## Последствия

- **Плюс:** registry и mapping становятся однозначными (один исполнитель, один путь).
- **Плюс:** резолвинг упрощается — нет KNOWN_PROFILES/fallback, нет resolve_profile с ветвлением.
- **Плюс:** контекст профиля mais — полный набор навыков 07.007 (как и было до ADR-003);
  монолитность компенсируется pipeline-механизмом (kanban, построчная генерация).
- **Минус:** префиксы `architect-*`/`regulator-*`/`crossfunction-*` сохраняются в именах
  навыков как функциональные маркеры — требуется аккуратность при grep-аудитах
  (имена файлов не переименовываются).
- **Минус:** требуется миграция: git mv всех навыков, обновление mapping/registry,
  скриптов, документации (blueprint, README, AGENTS.md).
