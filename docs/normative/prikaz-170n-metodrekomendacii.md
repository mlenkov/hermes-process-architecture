# Приказ Минтруда № 170н — Методические рекомендации

**Дата:** 29 апреля 2013 г.
**Полное название:** «Об утверждении методических рекомендаций по разработке профессионального стандарта»
**Статус:** Действует (с изменениями)

## Назначение

Рекомендации определяют порядок и правила разработки проектов профессиональных стандартов, включая:
- Формирование макета
- Описание трудовых функций
- Подбор формулировок
- Согласование и экспертизу

## Ключевые правила формулировок

### Трудовые действия (ТД)
- Формулируются как **глагольные существительные** в именительном падеже
- Отражают **конкретное действие** работника
- Каждое ТД должно быть **неделимым** (атомарным)
- Перечень ТД в рамках ТФ должен быть **достаточным и необходимым** для выполнения функции

Примеры правильных формулировок:
```
«Определение целей процесса»
«Сбор информации о ходе процесса»
«Оформление результатов контроля»
```

Недопустимо:
```
«Осуществление деятельности по управлению» — слишком общее
«Разработка, согласование и утверждение» — составное действие
```

### Необходимые умения
- Формулируются как **глаголы несовершенного вида** (что делать?)
- Должны быть **измеримыми** и **наблюдаемыми**

Примеры:
```
«Анализировать информацию о границах процесса»
«Разрабатывать локальные нормативные акты»
«Осуществлять коммуникации»
```

### Необходимые знания
- Формулируются как **существительные** (предметные области)
- Отражают **теоретическую базу**

Примеры:
```
«Теория процессного управления»
«Методы сбора информации»
«Нотации моделирования процессов»
```

## Соответствие уровням квалификации

Методика предписывает, что каждая ТФ в составе ОТФ должна соответствовать **одному уровню квалификации**. ТД внутри одной ТФ **не могут иметь разные уровни** — это единый блок.

## Связь ТД → умения → знания

```
ТД: «Сбор информации о процессе»
  → требуется умение: «Анализировать информацию»
  → требуется умение: «Выполнять наблюдения, интервью»
  → требуется знание: «Методы сбора информации»
  → требуется знание: «Теория процессного управления»

ТД: «Разработка регламента процесса»
  → требуется умение: «Разрабатывать схемы процессов»
  → требуется умение: «Осуществлять коммуникации»
  → требуется знание: «Нотации моделирования процессов»
  → требуется знание: «Требования к разработке регламентов»
```

Важно: один и тот же набор умений и знаний **обслуживает все ТД** данной ТФ. Нет привязки конкретного умения к конкретному ТД — это комплексная компетенция.

## Выводы для архитектуры

1. Умения и знания — **атрибуты ТФ**, а не отдельных ТД. Именно так они записаны в профстандарте
2. ТД — это **атомарная единица действия**, дальнейшая декомпозиция не предусмотрена
3. Порядок ТД в перечне имеет значение — это **естественная последовательность** выполнения
4. Все ТД одной ТФ требуют полного набора умений и знаний данной ТФ
