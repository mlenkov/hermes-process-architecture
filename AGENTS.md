# ARCHITECTURE — Архитектура профстандартов → Hermes Agent

Цель проекта — разработать и описать эталонную архитектуру, адаптирующую профессиональные стандарты РФ в исполняемые навыки Hermes Agent. В этой директории фиксируется **чистая архитектура** — как должно быть, без привязки к текущему состоянию сервера. Верификация и тестирование архитектуры выполняются на локальном Hermes.

## Ключевые директории

- `~/.hermes/` — локальная установка Hermes Agent (v0.18.2, git). Используется для тестирования архитектуры: развёртывания profiles, skills, проверки coverage. Обновлять через `hermes update`.
- `~/.local/bin/graphify` — graphify v0.8.44 (uv). Используется для построения графа знаний проекта. Исходники лежат в `../graphify/` (версия 0.9.18).
- `docs/standards/` — локальные копии профстандартов РФ (внешний источник данных), чтобы не скачивать при каждом запуске.

## Внешние источники

**Профстандарт 07.007** «Специалист по процессному управлению» — первичный входной документ. Скачан с classinform.ru, конвертирован в UTF-8, сохранён локально в `docs/standards/07.007.md`. Содержит 4 блока (A–D), 18 трудовых функций, 6 уровней квалификации.

## Шаблонная структура профстандарта

Парсер `scripts/parse-profstandart.py` выделяет 6 шаблонов:

1. **Титул** — регистрационный номер, дата регистрации в Минюсте, номер приказа Минтруда
2. **I. Общие сведения** — вид деятельности, цель, ОКЗ, ОКВЭД
3. **II. Описание трудовых функций** — функциональная карта (таблица ОТФ → ТФ)
4. **III. Характеристика ОТФ** — иерархия: ОТФ (metadata) → ТФ (трудовые действия, умения, знания)
5. **IV. Сведения о разработчиках** — ответственная организация, соисполнители

## Сборка графа

```bash
python3 ARCHITECTURE/scripts/build-graph-from-yaml.py ARCHITECTURE/docs/standards/07.007
```

Выход: `graphify-out/.graphify_semantic.json` — Dobsongraph-формат для graphify.

## Повторный парсинг

```bash
# Из HTML-файла
python3 scripts/parse-profstandart.py --file /tmp/page.html -o docs/standards/XX.XXX.md

# С сайта classinform.ru
python3 scripts/parse-profstandart.py --url https://classinform.ru/profstandarty/... -o docs/standards/XX.XXX.md
```

## Как это работает

1. **Профстандарт** → парсинг в YAML: `convert-md-to-yaml.py` (5 файлов: meta + 4 OTF-секции)
2. **Task-centric граф**: `build-graph-from-yaml.py` строит граф, где каждое Трудовое Действие (ТД) — центральный узел с атрибутами `action_verb`/`action_object`, профилем-исполнителем (`executed_by`), связями с умениями/знаниями и последовательными `next`-рёбрами
3. **Топология**: 315 узлов, 2263 ребра: 120 ТД → 18 ТФ → 4 ОТФ → 1 стандарт, + 1 профиль (mais, ADR-008), 98 skills, 70 knowledge, 5 hyperedge-групп
4. **Hermes** тестирует исполняемость: развёртывание skills, проверка coverage

## Нормативная база

Официальные документы, определяющие структуру профессиональных стандартов РФ — в `docs/normative/`:
- **Приказ 147н** — Макет профстандарта (форма и структура документа)
- **Приказ 148н** — Уровни квалификации (1–9)
- **Приказ 170н** — Методические рекомендации по разработке
- **structure.md** — Сводка: ОТФ → ТФ → ТД, умения/знания

Ключевое правило: **умения и знания описываются на уровне ТФ, а не отдельных ТД.**

## Pipeline Architecture (ТФ → ТД через Kanban)

Документ: `docs/pipeline-architecture.md` — формальная архитектура, верифицированная на локальном Hermes.

**Модель**: sequential chain — каждый ТД зависит от предыдущего через parent-child DAG. Первый ТД без parent (ready), последний ТД → TF-summary задача. `auto_promote_children: true` двигает pipeline.

**Seeding**: `scripts/seed-tf-pipeline.py` читает YAML → создаёт kanban-задачи.

**Тест (ОТФ-А, 2026-07-26)**: 4 ТФ, 24 ТД, full pipeline А/01.6 (10 ТД) выполнен последовательно. ✅

## Sandbox: ограничение на запись

**Запрещено писать файлы выше этой директории** (`/Volumes/Storage/work/mais/_TOOLS/VM-SRV001-SETUP/ARCHITECTURE/`).

Все генерируемые артефакты (outputs, данные pipeline, графы, схемы, навыки, конфиги) — только внутри `ARCHITECTURE/`. Исключение: деплой на сервер (`ai.mais.agency`) или в локальный `~/.hermes/`, но только по явной команде пользователя.

Ограничение **принудительно** на уровне OpenCode: `.opencode/opencode.jsonc` → `permission.external_directory: * → deny`. Доступ к `~/.hermes/` запрашивает подтверждение (`ask`). `write`/`edit` — только внутри `ARCHITECTURE/`. Destructive `bash` (`rm`, `mv`) — с подтверждением.
